# 内置宠物

插件随 `dsh-tauri-builtin` 分发，保留 `dsh-pet-lite` 标识以复用原有选择、尺寸和启用状态。首次启动由桌面宿主直接建立内置插件入口，不运行外部宠物程序或额外安装器。

宿主 HTTP 路由提供素材、导入和会话活动；渲染器只提交按下、松开、尺寸和动画轮廓。原生 `pet_native` 命令在主程序现有 Electron 运行时创建唯一的 `pet` 窗口。窗口不进入任务栏、不获得焦点，与主窗口的最小化和隐藏相互独立。Linux 的 Electron 不实现 `skipTaskbar`，因此对这种不接收焦点的辅助窗口使用工具窗口类型。

Rust 工作线程串行执行拖动和抛射，是唯一的位置写入者。松开时读取最终窗口坐标，空闲 300 毫秒后写入一次档案位置；拖动期间暂停布局、抛射和保存。视频透明像素和 Codex 图集当前帧转换为输入矩形，空白帧直接穿透鼠标。

Linux 原生 Wayland 不能自由定位、置顶或抛射，这些限制只警告一次。拖动交给合成器，点击时激活宠物窗口，避免点一下沉到别的窗口下面。设置中的 XWayland 开关在重启后恢复定位、置顶和抛射。macOS 的系统拖动优先使用运行时原生接口；X11 与 Windows 使用程序定位。跨平台行为仍需对应平台实机验收。

开发使用 `pnpm --filter dsh-pet-lite dev`。插件单独使用 tsdown 0.23.2，避免旧版在三入口监听时无法完成输出。使用 `pnpm exec vitest run --project unit packages/builtin-plugin-pet` 检查路由和轮廓。原生窗口回归位于 `tests/e2e/desktop/pet.e2e.ts`，使用隔离 home 和动态 CDP 端口；该夹具占用开发入口 1420，运行前应停止开发服务器。

人工验收：启用已有宠物；检查 Dock 无额外宠物应用，最小化或隐藏主窗口后宠物保留；连续拖动 20 次并检查松手落点与跨屏行为；开启抛射后检查边缘反弹；确认透明区域能点击下层窗口。原生 Wayland 下应能拖动宠物，单击后宠物留在前面；点回其他窗口后仍可能被挡住，且不能启用抛射。
